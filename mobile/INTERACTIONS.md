# 화면 흐름과 상호작용 계약

Figma 프레임에는 프로토타입 reaction이 연결되어 있지 않아 아래 흐름을 구현 기준으로 사용합니다.

M01 계정 연동 → M01 여행 스타일 → M02 반려견 프로필(1) → M02 반려견 프로필(2) → M03 여행 계획(1) → M03 여행 계획(2) → M03 장소 상세(3) → M03 여행 일정 확인(4) → M04 후기·장소 저장

## 공통

- 뒤로가기: 현재 화면의 임시 편집값을 유지한 채 직전 단계로 이동. 변경 손실 가능 시 확인 모달.
- 닫기: 온보딩/플로 종료. 미저장 값이 있으면 확인.
- CTA: 한 번 누른 뒤 중복 제출 방지, 로딩 상태, 실패 재시도.
- 모든 선택 요소는 눌림/포커스/선택/비활성 상태를 갖습니다.

## 상태 모델

- auth: provider, status, error.
- travelStyles: 선택된 스타일 ID 배열.
- petDraft: 사진, 종류, 이름, 품종, 몸무게, 생일, 성별, 중성화, 휴식 주기, 병원.
- party: petIds, guardianIds.
- tripDraft: 지역, 시작/종료일, 인원, 테마, 선택 장소, 출발지, 일정 항목.
- reviewDraft: placeId, rating(1–5), drivingTags[], comment.

## 검증 규칙

- 반려견 프로필(1): 종류, 이름, 견종, 몸무게, 생일, 성별, 중성화 필수.
- 반려견 프로필(2): 휴식 주기는 필수, 병원은 선택.
- 여행 계획(1): 반려동물 1마리 이상, 보호자 1명 이상.
- 여행 일정 저장: 출발지와 일정 장소가 필요. 비어 있으면 해당 행으로 포커스 이동.
- 후기: 평점 필수, 태그/한줄평은 정책에 따라 선택 또는 최소 글자 수 적용.

## 외부 연동 경계

- 계정 연동: OAuth 공급자별 어댑터.
- 병원 검색/장소 추천/후기: 서버 API를 UI 컴포넌트와 분리.
- Pleos/NaviHelper 연동은 모바일 와이어프레임 내부에서 직접 호출하지 않고 서비스 계층을 통해 차량 앱으로 전달.
- ‘이 여행지 추가하기’와 일정 저장 결과는 차량용 여행 계획 데이터와 동일한 도메인 모델을 사용.
