# PET:A 모바일 앱

Figma 파일 0GZeF5eDnZTc4TkWXA23XT, 페이지 3. WF (115:1583)의 요청 화면 9종을 직접 확인해 만든 구현 자료입니다. 화면 전체를 SVG로 굳히지 않았습니다. 원본 레이어에서 분리한 PNG/SVG 에셋, 화면별 렌더, 텍스트·폰트·위치 데이터, 상태와 상호작용 명세, Figma 기하학 참고 코드를 함께 제공합니다.

## 실행

```bash
npm install
npm run dev              # http://127.0.0.1:5173
```

- 시연용 기기 장식(상태 표시줄·홈 인디케이터)은 주소 뒤에 `?shell=1`을 붙이면 켜집니다. `?shell=0`으로 끕니다.
- 같은 Wi-Fi의 실제 폰에서 열려면 `npm run dev -- --host`로 실행합니다.
- `npm test`: 화면 흐름·검증·저장 API 테스트
- `npm run test:visual`: 402×886 시각 회귀 (Windows 기본 Edge 사용). 화면을 의도해서 바꿨다면 `npm run test:visual:update`로 기준을 갱신합니다.

## 차량 앱 연동

1. `npm run dev`를 켠 상태에서 에뮬레이터의 차량 앱(`../car`)을 실행합니다.
2. 모바일 M03 여행 일정 확인에서 ‘이 여행지 저장하기’를 누르면 `PUT /api/trip`으로 `.data/trip.json`에 저장됩니다.
3. 차량 앱은 C01 화면에 있는 동안 `http://10.0.2.2:5173/api/trip`을 3초마다 조회해 바로 반영합니다.

| 모바일에서 전달 | 차량 앱에서 아직 샘플 |
|---|---|
| 반려동물 이름·품종·나이·크기, 휴식 주기, 단골 병원 | 경유 휴게소(가평휴게소) |
| 목적지 이름·주소·임의 좌표, 날짜, 보호자 수 | 준비물, 경로상 거리 |

초기화: `curl -X DELETE http://127.0.0.1:5173/api/trip`. 저장된 여행이 없으면 차량 앱은 샘플 여행임을 표시합니다.

## 가장 먼저 볼 파일

1. SCREEN_SPEC.md — 9개 화면별 UI·상태·검증 기준
2. INTERACTIONS.md — 화면 흐름과 상호작용
3. design-tokens.json — 색상·타입·간격 기준
4. screenshots/ — Figma 원본 렌더 9장
5. assets/ — 로컬 저장된 원본 사진·SVG 128개

## 폴더 구조

- screenshots/: 402×886 원본 렌더 9장
- assets/: 화면별 원본 PNG/SVG
- asset-manifest.json: 에셋 이름과 로컬 경로
- reference/figma-structure.json: 텍스트·폰트·좌표·이미지 노드 데이터
- reference/figma-generated/: 절대좌표 기하학 참고용 TSX

## 구현 원칙

- reference/figma-generated의 TSX는 픽셀 위치 확인용입니다. 그대로 제품 코드로 복사하지 말고 재사용 컴포넌트와 정상적인 레이아웃으로 재구성합니다.
- Figma 임시 URL은 사용하지 않습니다. 모든 화면 에셋은 assets 안의 로컬 파일을 사용합니다.
- 402×886을 기준 뷰포트로 맞추되 콘텐츠는 max-width 402px와 유동 폭으로 구현합니다.
- 공통 요소는 MobileShell, TopNavigation, PrimaryButton, SelectionChip, PetAvatar, PlaceCard, BottomAction 등으로 분리합니다.
- 실제 모바일 앱이면 iOS 상태 표시줄·Dynamic Island·홈 인디케이터를 중복 구현하지 않습니다. 웹 데모에서만 MobileShell 장식으로 표시합니다.
- Figma에는 프로토타입 reaction이 연결되어 있지 않았습니다. INTERACTIONS.md의 흐름은 화면 문구와 컨트롤 상태를 바탕으로 정한 구현 계약입니다.
